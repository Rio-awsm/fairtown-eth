## Review Focus

1. **Event for a lot the client never saw listed** (joined mid-day, snapshot missed it). `lot.settled`, `bid.placed` or `handover.confirmed` for an unknown `lotId` must not crash. It sets status and shows a toast without money ("Lot 99 sold"). It does not place a stall. Test is in Task 3.
2. **The same envelope twice**: in `snapshot.recent` and again on the WS after a reconnect, or a duplicate fixture line. It is applied exactly once. Tests are in Tasks 5 and 8.
3. **Malformed frame or a `v: 2` envelope** from the relay. It is rejected, counted in `rejected`, logged with `console.warn`, and the stream continues. Test is in Task 5.
4. **Money above 2^53 base units, and `USDC`** (not an ISO 4217 code, so `Intl` throws a `RangeError`). Digits stay exact, and USDC prints as `USDC 12.50`. Test is in Task 2.
5. **A 7th open lot in one building.** It gets `slot: null` and never shares a slot. A slot freed by `paid_in_full`, `refunded` or `relisted` is reused by the next lot. Test is in Task 3.

### Task 5: Relay client (live) and replay client (mock)

**Files:** create `src/net/dedupe.ts`, `src/net/relayClient.ts`, `src/net/replayClient.ts`. Tests: `src/net/relayClient.test.ts`, `src/net/replayClient.test.ts`.

**Interfaces:**
- `class Deduper { constructor(max = 5000); seen(id: string): boolean }`: returns `true` if the id is already known, and records it otherwise. Oldest ids are evicted first.
- `type RelayStatus = "connecting" | "live" | "reconnecting" | "replay" | "replay_done"`
- `type RelayHandlers = { onSnapshot(s: TownSnapshot): void; onEnvelope(e: TownEnvelope): void; onStatus(s: RelayStatus): void; onReject(reason: string): void }`
- `type RelayClient = { start(): void; stop(): void }`. `start()` is idempotent, so a React StrictMode double effect doesn't open two sockets.
- `createRelayClient({ wsUrl, snapshotUrl, handlers, fetchImpl?, WebSocketImpl?, backoff?: { baseMs: 500, maxMs: 10_000 }, dedupe?: Deduper }): RelayClient`. The order matters:
  1. Open the WS and buffer incoming frames.
  2. `GET snapshotUrl`, then `TownSnapshot.parse`, then `onSnapshot`, and mark every `recent[].id` as seen.
  3. Drain the buffer through dedupe, then go `live`.
  4. On close, go `reconnecting` with exponential backoff, then repeat from step 1.

  A frame that fails `JSON.parse` or `TownEnvelope.safeParse` triggers `onReject` and a `console.warn`, then is skipped. If the snapshot fetch fails, the client closes the WS and goes to `reconnecting`.
- `createReplayClient({ jsonl, speed, handlers, schedule? = setTimeout })`:
  1. `onStatus("replay")`, then `onSnapshot(emptySnapshot)`.
