## 1. Packages

**`services/agents` (`@fairtown/agents`)**: Fastify 5 with pino. The logger redacts `authorization`, `*privateKey*`, `*mnemonic*` and `*accessKey*`. `src/config.ts` is a zod env schema covering only what 0.1 needs. `buildApp({ config, chain, arkiv })` is testable with `inject()`. `GET /api/health` returns `HealthResponse`, and errors use `{ error: { code, message } }`. `CHAIN_MODE=anvil|base-sepolia` fails fast until S2 3.1 adds ViemChain.

**`services/relay` (`@fairtown/relay`)**: Fastify serves `/health`, `/snapshot` and `/internal/publish` (bearer `RELAY_INTERNAL_TOKEN`, body `TownEnvelope[]`). A `ws` server in `noServer` mode serves `/ws` with ping/pong heartbeats. `state.ts` drops envelopes whose `id` was already seen, keeping a bounded set, and folds each one into a `TownSnapshot` with lots, agents, signals, fx, block and the last 200 envelopes. `--replay <file> --speed N` plays envelopes using their `ts` gaps divided by N. A client whose `bufferedAmount` passes the limit is dropped. Chain watching and reconnect come in S2 4.1.

## 2. ChainAdapter and FakeChain

The interface follows the guide's method list, using `bigint` and `Address`. Writes take the acting wallet `from` and return `{ tx, ... }`. `watch(handler)` emits decoded logs in contract section 7 shape: `{ eventName, args, blockNumber, transactionHash, logIndex }`. The mapping to `TownEvent` stays in the relay (S2 4.1).

FakeChain keeps all state in memory: balances, roles, Permit2 approvals, lots, bids, held money, tickets and seller records. Time moves on a manual block clock: `mine(n)`, plus `autoMine(ms)` for dev. Each violated rule throws a `ChainError` with a code named after the revert:
- The caller must be able to list or bid.
- The currency must be on the allowlist.
- `perUnit` must be at least 1000.
- A bid must be on a tick, above clearing, with Permit2 set up, and before `endBlock`.
- A ticket must carry a valid signature (`signTypedData` with `handoverDomain`, checked with `recoverTypedDataAddress`), come from the buyer or the carrier, be unexpired and be unused.
- A no-show report must come after `pickupDeadline` and inside the report window.

On each `mine()`, the auto-keeper does what the S1 keeper will do:
- At `endBlock` it settles: uniform clearing, then `splitPayout` with the advance for the seller's tier (truck 10%, proven 90%, new 50%). It emits `LotSettled` with `pickupDeadline = endBlock + pickupWindow(sector)` and emits `TransportNeeded` for produce, fish and flowers.
- When a truck lot with a parent settles, it assigns the carrier.
- After the contest window passes uncontested, it finalizes the no-show.
- After the report window closes, it releases expired held money.

Handover releases held money in proportion to the tokens handed over, and rounding dust goes to the seller on the final release. A direct pickup emits `LotDelivered(lotId, 0)`, and a truck delivery emits `LotDelivered(parent, truckLot)`. `LotPaidInFull` fires only when both the parent's and the truck lot's held money are fully released. Clean lots increment `cleanLots`. A finalized no-show resets it and clears `proven`. Test hooks: `resolveRuling` (stands in for W3) and `markProven` (stands in for the operator).

Invariants: `sellerPaid + fee + held == raised`, and at the end `seller + buyers + treasury == raised`.

The user writes the clearing-price function. It is scaffolded with its signature and tests.

## 3. ArkivStore

`put(schema, values, { owner, expiresInBlocks, key? })` creates an entity, or replaces it when `key` is given. The other methods are `extend(key, blocks)`, `query(schema, where, { limit <= 100, orderBy, cursor })` and `watch(handler)`. A schema is a minimal descriptor, `{ name, indexed: string[] }`. The seven real schemas come in S2 2.1 through their own ICR. `MemoryArkivStore` copies Rabdi's behaviour: only indexed columns can be filtered, pages hold at most 100 rows, watch events carry no attributes, expiry emits no event, and payloads are capped at 100 KiB.

## 4. Fixtures

`services/agents/scripts/gen-fixtures.ts` writes to `packages/shared/fixtures/`:
- `day.jsonl`: about 300 envelopes with ids `day-0001` onward and rising blocks. It covers every `TOWN_EVENT_TYPES` entry across all 7 scenes, including Coastal Catch's no-show and one dispute. Money comes from `splitPayout`, for example Bergen: 5,460.00 EUR raised, 54.60 fee, 2,702.70 paid now and 2,702.70 held.
- `agents.json`: 27 personas per D-18, each with currency, budget, mandate, place and building, plus seeded proven and no-show flags.
- `messages.json`: 20 seller messages with expected parses, covering tonnes, quintals, pounds and local words. 2 are hard on purpose, matching the step 1.2 target of 18 of 20.

Running the generator again produces byte-identical output.

## 5. Doctor rows (`scripts/doctor/checks/s2.ts`)

- **Arkiv:** memory mode passes as ok. Live mode checks the access key is set and the chain ID is 7794095. The keyed RPC URL is never printed.
- **LLM:** `MOCK_AI=1` passes as ok. Otherwise it calls `GET {LLM_BASE_URL}/models` and checks the configured models are listed.
- **Ports:** 8787, 8788 and 8790 are free.
- **Add-ons:** for each enabled `ADDON_*` flag, its env vars are set.

`fetch` and `net` are injected so the rows can be tested. The funded-agents row comes in S2 3.1.

## 6. Tests

- **Config and health:** env validation and the `/api/health` route.
- **FakeChain:**
  - Bergen with exact numbers.
  - The truck chain through to paid in full.
  - The no-show refund and record update.
  - Relist, dispute and ruling.
  - Ticket failures: wrong signer, expired, reused, wrong sender.
  - Bid failures: off tick, below clearing, no Permit2, auction ended.
  - The money invariants.
- **MemoryArkivStore:** filters, paging, expiry, extend, watch.
- **Relay:** replay order and speed, dedupe, snapshot, publish auth (401 and 400), and a real WebSocket client receiving broadcasts.
- **Fixtures:** every line parses, every event type and scene is covered, money is consistent, persona counts match D-18, and regeneration is deterministic.
- **Doctor:** S2 rows in mock mode.
